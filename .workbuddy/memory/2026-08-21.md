# 2026-08-21

## EXCEED_AUTHORITY 前端加载失败 → 改为密码登录（已解决）

**问题**：admin.html 用 `signInAnonymously` + `callFunction`，浏览器报 `EXCEED_AUTHORITY`。

**排查结论**：
- PG 模式下云函数 HTTP API（`/v1/functions/<name>`）对**匿名用户默认不放行**（官方网关默认策略表：functions 仅管理员/注册用户）；匿名 token curl 复现同样报错
- 控制台「身份认证 → 权限控制」（角色策略绑定 FunctionsHttpApiAllow）在 PG/个人版环境**不可用**：MCP 角色管理 API 直接返回 "does not support PostgreSQL type environments"；权限控制 RBAC 页面官方声明仅适用传统模式
- OPA 用户策略（authz.user.rego）`default allow := true` 无法放开匿名调函数（实测无效）——OPA 是另一层
- **关键验证**：注册用户（用户名密码登录，role=authenticated）token 调 `/v1/functions/customers` 成功返回 761 行

**解决方案**：
1. `managePermissions createUser` 创建 `crm_admin` 用户（密码 CrmTest2026!secure，建议用户改密）
2. admin.html 重写认证：`signInAnonymously` → 登录表单 + `auth.signInWithPassword({username,password})`，`hasLoginState()` 恢复会话，persistence:'local'
3. 已部署静态托管并验证线上代码更新
4. OPA rego 收口：显式 `deny` 匿名/unauthenticated/anon 调 functions（纵深防御）
5. 双向验证：密码用户调用成功 ✓；匿名调用被 rego 拒绝（ACCESS_DENIED: anonymous access to functions is not allowed）✓

**技术要点**：
- v3 SDK 方法确认：`t.prototype.signInWithPassword=function(e)` 接受 `{username,password}`（email/phone 亦可），`signInWithUsernameAndPassword` 是另一个旧方法
- HTTP API `/auth/v1/signup` 不支持纯用户名密码注册（"请前往云后台创建"），须用 MCP createUser 或控制台
- RLS 安全模型不受影响：浏览器 token 带 `sub` 仍被 RLS 拦截，数据访问必须走云函数（函数 token 无 sub）
- 静态托管部署：`manageHosting upload` localPath=admin.html cloudPath=index.html
