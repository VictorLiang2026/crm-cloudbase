# 后续开发安全边界说明

> 适用版本：v1.0.4（2026-09-06 建立基线）
> 来源：v1.0.4 全量代码与数据库结构只读检查（前端 admin.html、16 个云函数、13 表 8 视图）。
> 用途：之后每次修改前对照执行，防止破坏已上线功能。最新架构事实参见 `docs/architecture-current.md`。

## 一、架构红线

1. **保持 admin.html 单文件架构**，不引入 Vue/React/Webpack/构建链。
2. **前端读写数据一律走 `callFn`**；除增员附件私有桶 `recruit`（上传/签名/删除）外，不得新增 `app.rdb()` / `app.storage` 直连。
3. 不新增表、字段、视图、云函数，除非需求明确要求并走迁移流程（迁移文件双备份：`cloudbase/migrations/` 与 `C:\Users\victor\cloudbase\migrations\`）。

## 二、数据库红线

4. **基表加列/改列后必须重建依赖视图**（DROP VIEW → CREATE VIEW 含新列 → re-grant SELECT），并同步验证云函数与前端字段。视图不会自动包含后加的列（历史踩坑：`v_recruit_candidates` 缺附件字段）。
5. 新增视图**不要授权给 authenticated**；当前 8 个视图均未启用 security_invoker（以 owner 身份绕过基表 RLS），不得再扩大该暴露面。
6. **RLS fn_only 策略是数据安全底线**：任何新表必须加 `*_fn_only` 策略（仅匿名上下文可访问）；云函数必须保持匿名通道（rdb）访问，不得引入登录态直连。
7. 删除语义不得混改：客户/候选人删除 = 软删除 + 级联（**同一 deleted_at 时间戳**标记主表+子表）；子记录（跟进/礼品/照片/检视报告/AI解析/产品额度/增员跟进）单独删除 = 硬删除不进回收站。

## 三、云函数红线

8. **db.js 是按目录复制的（17 份，现存 5 个变体）**：改 `_shared/db.js` 或任何副本后，必须同步全部受影响函数目录并重新部署该函数；`_shared/` 母本本身不会自动生效。不主动"统一"各变体，只在动到某函数时顺带对齐。
9. AI 函数超时是真实约束（recruit_score 60s；ai_recommend / ai_parse / recruit_recommend / policy_review generate 120s），勿在其中叠加长链路同步调用。
10. AI 结果落表遵循现有模式：ai_recommend 只追加 `ai_recommendations` 建议记录、不覆盖客户字段；ai_parse 对已有客户不直接覆盖字段，附加信息以 `===================` + 日期追加；AI 删除记录需支持恢复到解析前快照（ocr_records.customer_snapshot）。

## 四、前端红线

11. 改 `el()` / `callFn` / `ensureSession` / `computeWbStatus` / `renderCustomerTable` / `route()` 前，**先 grep 全部调用点**——它们被所有页面共享（见下表 R1-R5）。
12. 客户列表保持 11 列契约（iPhone 短表头）/ iPad 全表头 / 分页 ≤50 / 统计卡点击排序 / 表头点击排序 / 回收站行为，均不得回归。
13. admin.html 必须保留 `<meta http-equiv="Cache-Control" content="no-cache, no-store, must-revalidate">`；发布走 `tools/release.ps1`，`tools/sync-check.ps1` 体检全绿才算完成。
14. 敏感文件（数据库信息.txt 等）与测试文件永不入库、不部署到托管；部署用 MCP `manageHosting`，不用 `tcb hosting deploy`。

## 五、修改纪律

15. 小步提交：一次只动一条数据流；改前跑 sync-check 确认基线干净。
16. 涉及 cloudfunctions 的提交，部署后必须实际调用验证（云函数无 MD5 比对手段，靠部署时确认）。

## 附：知情保留项（不要"顺手清理"）

- 6 个 `*_view`（customers/followups/gifts/photos/products/ai_recommendations_view）代码中已无消费者，属历史遗留，保守保留不删。
- `policy_review_reports/db.js` 为旧注释版变体，功能无冲突。
- 分页+排序逻辑在 5+ 处各自实现（无共享 helper）——仅在顺路改到时统一，不做专项重构。
- 日期分桶两套口径并存且各自正确：云函数按北京 +08:00（toDayKey），前端按本地时区（dayStr/diffDaysTo），不可互相"统一"。
