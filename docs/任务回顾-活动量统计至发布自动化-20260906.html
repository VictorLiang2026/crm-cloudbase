1活动量日报（客户经营 + 增员双维度）

需求背景 云函数 activity_reports

为 CRM 增加两套「活动量日报」，参考 LIMRA/MDRT 活动量管理与增员漏斗经验：

  • 客户经营日报：入口在今日工作台工具栏；
  • 增员日报：入口在增员列表工具栏（目标管理右、回收站左）。

口径约定（用户确认 3 点）：

  • 按业务发生日期归属（补录算回原日期）；
  • 客户经营无件数/保费，用「保单检视 + 额度更新」代理；
  • 增员 AI 话术/评分不落库，一期不统计。

实现做法

  • 后端：新建云函数 activity_reports（index.js / db.js / package.json），两个 action：customer、recruit；两种模式：today（默认，实时）与 range（开始/结束日期，上限 366 天）。
  • 纯读聚合：不新增表、不改写入逻辑；全量裁列 select + JS 按北京日期分桶（与回收站同模式）。
  • 客户指标：新增客户、首次接触、跟进、接触客户数、计划到期、已完成计划、完成率、礼品、照片、OCR 解析、AI 建议、保单检视、额度更新等。
  • 增员指标：新增候选人、跟进、漏斗 6 阶段（暖客→初面→活动→精准面谈→申请→入职），阶段由 recruit_milestones.to_stage 映射；当月目标对照内部复用 recruit_goals 的 getProgress。
  • 前端：通用 renderActivityPage(opt)：今日实时/区间切换、指标卡分组（区间显示日均）、逐日趋势表、活动流水（彩色 badge，上限 300 条）、增员页目标对照表。

上线后两轮 Bug 修复 用户线上反馈

Bug A：入口一（工作台「活动量」按钮）没出现；入口二点击跳到 #/

  • 根因：之前同一文件的多个 Edit 放在同一并行批次，工作台按钮被增员页那处覆盖丢失；
  • 修复：补回工作台按钮；跳 #/ 经无头 DOM 测试证明路由无跳转逻辑，判定为部署瞬间浏览器/CDN 缓存，建议无痕窗口验证。

Bug B：入口二报「Failed to execute 'appendChild' on 'Node': parameter 1 is not of type 'Node'」整页加载失败

  • 根因：增员日报「当月目标对照」表把数字（目标 60、实际 10）直接塞给 appendChild，真实 DOM 只接受 Node，渲染中途抛错 → 整页 catch 成"加载失败"；无头桩因为 appendChild 太宽松没暴露；
  • 修复：公共 el() 加类型兜底（数字/布尔自动转文本节点）+ 目标表显式 String()；空数据正常显示"暂无记录"，不再白屏。

验证方式

  • 云函数：线上 invoke 实测 today / range 两种模式数据正确（如客户 9/1-9/5：跟进 4、完成率 16.7%；增员 today：新增 10、暖客 3）。
  • 前端：Node 最小 DOM 桩跑通整个内联脚本（后升级为严格桩：appendChild 拒绝非 Node、innerHTML='' 真实清空子节点），路由渲染、hash 稳定、无运行时错误。
⚠ 踩坑记录（时区）：dayList 最初用 new Date(start+'T00:00:00+08:00') + toISOString().slice(0,10) 导致日期标签整体回退一天；改为 UTC 算术（new Date(start+'T00:00:00Z') + setUTCDate 递增）后修复。
